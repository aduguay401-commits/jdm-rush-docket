# JDM Rush Docket product map

Source baseline: `main` at `0070afe`, consolidated 2026-09-13 from coder, reviewer, designer and tester `SCOUT_REPORT product-map-01` reports, with independent source corrections. **CONFIRMED** means implemented in inspected source, not verified deployed, configured, migrated or exercised. **QUESTION** requires operator/runtime evidence. This document is not a production audit.

## Product and stack — CONFIRMED

Docket is a sourcing CRM, token-based pre-sale home base/report, and authenticated post-approval My Garage. It combines landed-cost estimates, manual research, agreement/deposit gates, manually maintained delivery tracking, and consent-based inventory nurture. It is not an automated purchasing/payment platform.

- `package.json`: Next 16.2.2 App Router, React 19.2.4, TypeScript, Tailwind 4; Supabase Auth/Postgres/Storage; nodemailer, Twilio, pdf-lib, react-markdown. Scripts: dev, build, type-check, lint, test (`vitest run`). `vitest.config.ts` provides the `@` alias; no browser test configuration.
- `next.config.ts` is empty; `middleware.ts` refreshes Supabase cookies, not route authorization. `vercel.json`: follow-up daily 14:00 UTC; nurture matches Monday 15:00 UTC. Configuration presence does not prove execution.
- `app/layout.tsx` loads Outfit with next/font/google; `app/account/layout.tsx` uses Manrope. Google font fetching is an offline-build dependency to verify.
- `AGENTS.md` correctly names nodemailer and Vitest. `CLAUDE.md` still claims Resend/no tests and understates the portal. README is create-next-app boilerplate; lifecycle roadmap's planning header and older seat states are not reliable implementation status.

## Trust boundaries — CONFIRMED unless marked QUESTION

| Actor / boundary | Actual authorization and operations |
| --- | --- |
| Staff | `lib/admin/auth.ts` obtains cookie-auth user, then `profiles.role` through the anon client using **profiles.id = user.id**. Recognized roles: admin, agent, customer. Existing requireAdmin/requireAdminOrAgent guards protect staff APIs. There is no defensive `id OR user_id` lookup in this helper. |
| Admin | Admin pages require admin; admin APIs guard access. `app/api/admin/dockets/[id]/route.ts` additionally permits agents only for research_draft/vehicle_description edits. Agent creation/deletion is admin-controlled. |
| Agent | Agent dashboard/detail use browser anon Supabase with RLS; UI access does not authorize a separate API request. Guarded APIs include docket PATCH, license files, invoices, shipments, rollback-research, move-to-delivery and send-agreement. No per-agent docket assignment/scoping is implemented in the inspected model. |
| Service role | `lib/supabase/server.ts`'s createServerClient is the **service-role** client, bypassing RLS. `server-auth.ts` is the anon cookie client; `client.ts` the browser client. Route authorization is essential before service-role work. |
| Token customer | Report/questions UUID tokens authorize server-side service-role lookups without login. Token pages/APIs have no observed expiry/revocation/publication gate or lookup rate limit. Browser token policies were removed in migration 008. Nurture token handling separately has in-memory limiting. |
| Account customer | `lib/customer/auth.ts` provisions customer records, preserves staff profile roles, claims unowned matching-email dockets, and rejects disabled customers. Ownership is customer_id -> customers.auth_user_id; portal queries use cookie client + RLS. File handlers verify ownership before privileged storage signing. Login checks trusted origin. |
| Machine | Follow-up/nurture crons require Bearer CRON_SECRET, fail closed when unset. Twilio SMS status callback validates signature. ASNET proxy requires x-api-key matching INTERNAL_API_KEY. |
| Public | Intake/quote have fail-open abuse controls, not login. Pricing estimates, import calculator and fixed test-calculator have no observed auth/rate limit. Match preview is available only with DEV_MODE=true, not staff auth. |

**Confirmed security finding at baseline:** POST `app/api/agent/proceed/route.ts`, `app/api/agent/send-questions/route.ts`, and `app/api/agent/research/[id]/route.ts` lack role/session guards. Knowing a docket ID permits service-role status/history writes, question inserts/customer notifications, or research replacement/cost/status writes. Research notification goes to **admin**, not customer (correction to reviewer scout wording). Docket UUID difficulty is not authorization. Independent coder/reviewer source confirmation established the gap; remediation is the separate guard/test commit in this task. No exploit or production request was performed.

## Lifecycle and route map — CONFIRMED

1. **Entry is two flows.** `app/api/system/intake/route.ts` creates find_my_jdm dockets (or trusted proxy-attributed rush_whatsapp), stores customer/preferences/destination/FX, and notifies participants. `app/api/system/quote/route.ts` computes an immediate inventory-price estimate, creates exact_quote, emails the estimate and may create an inactive nurture search. Quote is not a researched report: selected_path is `quote-endpoint`, estimate text lives in additional_notes, and response reportToken actually contains questions_url_token. The external form/inventory frontend is not established as living here.
2. **Abuse defenses.** `lib/intake/guardrails.ts`: honeypot/fill time, per-IP 5/hour (trusted proxy header or x-real-ip), per-email 4 dockets/day, welcome-email 2/day. Failures degrade open. Quote also reuses recent email/reference dockets. Missing proxy configuration weakens IP attribution.
3. **Working queue.** `/agent/dashboard` has Needs You/Working/Cold/All triage, working-lead vs Quote Pool split, same-person grouping, pins/archive, unread/activity and SMS telemetry. `lib/dockets/{dashboardDisplay,activityFeed,leadSource}.ts` owns shared display/source logic. Detail `/agent/docket/[id]` supports request editing, questions, drafts, preview, research, closeout, invoices and shipments. Draft autosave uses the restricted admin PATCH API.
4. **Clarification.** `/api/agent/send-questions` inserts marcus_questions and changes initial new -> questions_sent. `/questions/[token]` is a persistent status-aware home base; `/api/customer/questions/[token]` stores answers and changes questions_sent -> answers_received. Token ask/report-question and authenticated `/api/customer/messages` store additional customer questions. Proceed sets research_in_progress; rollback-research uses history to restore a permitted prior state.
5. **Research.** `/api/agent/research/[id]` validates auction/dealer input, loads destination/type/duty, fetches FX, calculates totals/ranges, replaces research/estimate rows, stores recommendation/FX, and sets report_sent/history. `/agent/docket/[id]/preview` also computes/persists money fields: preview is not a guaranteed read-only sandbox. Research submission sends email_4_report_ready to ADMIN, despite report_sent status. `/api/admin/remind/[id]` can email the customer report link.
6. **Report.** `/report/[token]` loads stored research/fees and signs media URLs; `ReportClient.tsx` renders options, costs, questions and approval. It reads persisted report costs rather than recomputing at view time. Token existence alone permits access; no report_sent publication check was found.
7. **Decision.** Canonical `/api/customer/approve/[token]` chooses auction/private_dealer, writes decision_made plus chosen/selected compatibility fields and approved_at where supported, enrolls Sequence C and emails next steps. Legacy `/api/customer/report/[token]/decision` returns 410. `lib/invoiceStub.ts` only emails admin that a **$1,500 CAD deposit invoice is required**; no QuickBooks issuance or payment collection occurs there.
8. **Agreement.** `/api/agent/send-agreement` sends a registration/login signing link. `/account/docket/[id]/sign` and its customer API require authenticated docket access, collect address/signature/license, create/hash/store PDF and audit/signature rows, set agreement_signed and send the PDF. `lib/agreements/templates.ts` accepts only real auction/private_dealer paths and rejects quote-endpoint; storage helpers use private document/agreement buckets.
9. **Invoice/closeout.** InvoiceLedger and `/api/agent/invoices/*` maintain a manual ledger with uploaded files or external QuickBooks URLs; amount is staff-entered, not reconciled to calculator output. Marking a deposit invoice paid sets deposit_paid; reversal does not automatically clear the docket flag. `/api/agent/move-to-delivery` atomically requires decision_made + signed + paid before sold_in_delivery, then best-effort creates shipment.
10. **Delivery.** ShipmentPanel and `/api/agent/shipments/*` maintain vehicle/vessel/ports/ETA/tracking and forward-only stages with history/CAS. `lib/shipments/stages.ts`: pre-shipment, purchased, at-port-japan, vessel-booked, departed-japan, arrived-canada, clearing-customs, cleared-customs, on-transport, delivered. These are shipment stages, **not docket statuses**; delivered does not automatically clear the docket.

Docket display statuses (`lib/dockets/dashboardDisplay.ts`): new, questions_sent, answers_received, research_in_progress, report_sent, decision_made, sold_in_delivery, cleared, lost, paused, unresponsive. Schema status is text, not an enum. Mark-lost is admin-driven; follow-up can mark unresponsive. No dedicated cleared/paused transition UI was found, but free-text admin status editing means they are not strictly unreachable. Reviewer scout's report_question_sent/customer_followup_question_sent/delivered lifecycle list should not replace this canonical display list.

**QUESTION F1:** Who performs the initial customer report release? Research's admin-only notification is confirmed; manual handoff/external automation is not. **QUESTION F2:** Quote-to-approval may reject the truthy quote-endpoint sentinel as already approved unless something clears it; investigate separately, along with report readiness and dealer selection validation. **QUESTION F3:** Multi-step research replacement, approval, intake and signing are not one transaction; establish retry/idempotency expectations. **QUESTION F4:** Decide completion/paused ownership and whether delivered should clear the docket.

## Pricing, integrations and automation

**CONFIRMED:** `lib/importCalculator.ts` is shared quote/research/public-pricing math. Shipping/insurance 250,000 JPY; excise CAD 100; GST 5%; terminal 508.77; brokerage 375; network 800; finance/admin 225; 0/6.1% duty; city/type inland transport; tiered Export Agent Fee and JDM Rush fee. Card estimate subtracts inland transport. Fees are code constants, not DB-managed. `lib/exchangeRate.ts` fetches Bank of Canada FXJPYCAD; on failure returns 0.0092 with today's date. **QUESTION P1:** Is indistinguishable fallback acceptable? Confirm GST-only/provincial-tax customer promise.

**CONFIRMED notification distinctions:**
- `lib/email.ts` is Gmail SMTP/nodemailer; DEV_MODE recipient routing is in callers, not a central sendEmail enforcement. Dev emails may still use real SMTP/admin inbox.
- `lib/sms.ts` uses Twilio and sms_log; no central DEV_MODE suppression. The sole observed send-questions call site **does check `!devMode && customerPhone`**, awaits sendSMS and catches failures without failing the response. Its fire-and-forget comment is inaccurate; do not claim dev send-questions always sends SMS.
- `lib/whatsapp.ts` uses **CallMeBot**, not Twilio, for internal agent notifications; no central DEV_MODE protection. `lib/rush.ts` renders a customer-facing wa.me handoff link (not a send).
- `/api/webhooks/twilio/sms-status` validates signature using canonical app URL and updates telemetry; configuration must match Twilio callback URL.

**CONFIRMED:** `lib/inventory/japanStock.ts` loads configured/default Cloudflare R2 JSON for pricing and nurture. ASNET proxy calls configured bot /search; no UI caller found. **QUESTION I1:** ASNET live vs dormant, bot configuration/operation and external site/proxy integration are not proven by this repo.

**CONFIRMED:** Follow-up cron implements A/B/C three-step sequences, due-row claim/log dedupe, daily cap 50, stops for archive/cleared/lost/sold-in-delivery/signed. Only C enrollment is found in app/lib; **QUESTION A1:** A/B may be externally/DB enrolled; calling them definitively dead exceeds evidence. Nurture migrations 010–012, consent/matching/model modules, token double opt-in/unsubscribe, saved searches and send audit are implemented. Quote feature flag gates enrollment, not the cron schedule. Weekly matching checks active consent/unsubscribe and recent sends, selects up to three matches. **QUESTION A2:** Live flags, consent, migrations, inventory and scheduling unverified. No automatic auction purchase, carrier synchronization, QuickBooks issuance or legal cleanup established.
